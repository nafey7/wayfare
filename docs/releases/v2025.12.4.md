## Summary

This release focuses on **stability and UX improvements** across the booking flow, with notable fixes for payment form initialization, token expiration handling, and flight filtering. The backend also underwent significant cleanup (-1,196 lines of dead code) and migrated to a new AI SDK.

### Highlights

- 🎨 **New compact flight display** with category tabs (Cheapest, Fastest, Best Value)
- 🔐 **Automatic token refresh** prevents losing booking progress
- 💳 **Fixed payment form** not loading from email links
- 🧹 **1,196 lines of dead code removed** from AI handlers
- 🤖 **Migrated to new Google GenAI SDK** (vendor-agnostic architecture)

## Detailed Changelog

### #121 - Compact Flight Display with Categories

**Type**: Feature
**Files Changed**: Backend (enhanced_flight_handler.py), Frontend (FlightResultMessage, ChatBot)

**What changed**:
- Flight search results now display in a compact card format with category tabs
- Three categories: **Cheapest 💵**, **Fastest ⚡**, **Best Value ⭐**
- Maximum 10 flights shown per category
- Backend returns new `flight_search_results` response type with structured `data.categories`
- Added city names (origin_city, destination_city) to response

**User impact**: Easier to find optimal flights without scrolling through long lists.

---

### #140 - Google GenAI SDK Migration

**Type**: Feature (Internal)
**Files Changed**: New `integrations/llm/` module, intent_recognizer.py, requirements.txt

**What changed**:
- Migrated from deprecated `google-generativeai` to new `google-genai>=1.0.0` SDK
- Created vendor-agnostic `LLMService` protocol for future flexibility
- New module structure:
  - `integrations/llm/protocol.py` - LLMService Protocol
  - `integrations/llm/gemini.py` - GeminiLLMService implementation
  - `integrations/llm/dto.py` - Response data classes
  - `integrations/llm/exceptions.py` - Typed exception hierarchy
- IntentRecognizer now uses dependency injection for LLM service

**User impact**: None - internal architecture change.

**Dependency change**: `google-generativeai` → `google-genai>=1.0.0`

---

### #139 - Stripe Payment Form Initialization

**Type**: Bug Fix
**Files Changed**: email/builder.py, flight-booker/index.html

**What changed**:
- Payment page URL now uses `BACKEND_URL` from settings instead of hardcoded DEBUG-based logic
- Added DOM element validation before Stripe initialization
- Enhanced price extraction with `bookingResult.trip_details` fallback for email payment links
- Added `fetchTripDetailsForPayment` function to retrieve full trip details
- Added retry logic for DOM element availability with timeout fallback
- `loadBookingFromReference` now auto-initializes Stripe payment form when loading from email links

**User impact**: Payment form now loads correctly when clicking payment link in confirmation email.

---

### #125 - Automatic Token Refresh

**Type**: Bug Fix
**Files Changed**: auth.py, flights.py, flight/service.py, flight-booker, hotel-booker

**What changed**:
- Implemented automatic token refresh on 401 errors in flight-booker and hotel-booker UIs
- Added `InvalidTokenError` exception handling in flight API endpoints
- Access token expiration now uses configurable `ACCESS_TOKEN_EXPIRE_MINUTES` setting
- Refresh tokens stored in localStorage for both frontend UIs
- New `fetchWithTokenCheck` wrapper auto-refreshes tokens and retries failed requests

**User impact**: Users no longer lose their booking progress when JWT token expires during a session.

---

### #126 - FlightLogic Credentials Exposed in Logs

**Type**: Security Fix
**Files Changed**: flightlogic/client.py, terraform ECS config

**What changed**:
- Masked API credentials in log output
- Updated logging to prevent sensitive data exposure

**User impact**: None - security improvement.

---

### #113 - One-Way Flights Incorrectly Filtered

**Type**: Bug Fix
**Files Changed**: flight-booker/index.html

**What changed**:
- `updateFilterStateFromUI()` now treats default slider values (0/24 for duration, 0/1440 for time) as `null` instead of active filters
- `filterFlights()` now skips inbound duration filter for one-way flights when `inboundHours` is null
- One-way flights no longer incorrectly filtered by inbound duration slider

**User impact**: Fresh one-way searches now display all available flights without unexpected filtering.

---

### #115 - Hotel Booking 404 on Email Link

**Type**: Bug Fix
**Files Changed**: hotels.py, email/builder.py, hotel/service.py, hotel-booker

**What changed**:
- Fixed 404 error when clicking booking details link in confirmation email
- Fixed navigation display problems in hotel booking flow
- Updated hotel domain events and schemas

**User impact**: Hotel booking confirmation emails now link correctly to booking details.

---

### #117 - Flight Storage Quota Exceeded

**Type**: Bug Fix
**Files Changed**: flight-booker/index.html

**What changed**:
- Added `MAX_FLIGHT_RESULTS` constant (200) to limit stored flight data
- New `prioritizeAndLimitFlights` function sorts by stops (direct first, then 1-stop, then 2+)
- Flight limiting applied to both cached and API results before sessionStorage
- Added try-catch error handling around `sessionStorage.setItem`
- Status messages now show original vs displayed counts when limited

**User impact**: Large flight searches no longer crash the browser due to storage quota exceeded errors.

---

### #107 - Geolocation/Search Issues in Flight Booker

**Type**: Bug Fix
**Files Changed**: airports.py, flight-booker/index.html

**What changed**:
- Fixed airport API endpoint issues
- Resolved flight booker search problems related to geolocation

**User impact**: Airport search and geolocation features work correctly.

---

### #124 - Dead Code Removal

**Type**: Improvement (Internal)
**Files Changed**: Multiple AI handler files

**What changed**:
- Deleted `data_extractor.py` (-676 lines) - completely unused
- Deleted `response_generator.py` (-358 lines) - completely unused
- Removed dead methods from `response_enhancer.py` (-70 lines)
- Removed unused `_format_flight_rules()` from `flight_summary_generator.py` (-24 lines)
- Fixed intent bug: removed "to " from FLIGHT_KEYWORDS (was matching date ranges like "Jan 5 to 10")
- Extracted `DateParser` and `SelectionParser` utilities with unit tests

**User impact**: Improved intent recognition - date ranges like "Jan 5 to 10" no longer incorrectly trigger flight intent.

---

### #120 - Hotel Booker Backward Navigation

**Type**: Improvement
**Files Changed**: hotel-booker/index.html

**What changed**:
- Added `clearInvalidatedData` function to clear downstream data when navigating backward
- Data clearing integrated in:
  - `handleHotelSearch` - clears hotel, room, and guest data when search changes
  - `selectHotel` - clears room and guest data when hotel selection changes
  - `confirmRoomSelection` - clears guest data when room selection changes
- Added validation checks for `selectedHotel`, `flightlogicSessionId`, and `viewingRoomDetail`
- Step completion indicators reset when upstream data is cleared

**User impact**: Navigating backward in hotel booking now properly clears stale data from previous selections.

---

### #112 - AI Handler Characterization Tests

**What changed**:
- Added 170+ characterization tests documenting current AI handler behavior
- FlightLogic mock server integration for deterministic test results

### Known Issues / Limitations

1. **LOG_LEVEL set to DEBUG**: May produce verbose logs in production. Consider changing to `INFO` after initial monitoring.

2. **Flight category limits**: Maximum 10 flights per category - users with specific requirements may need to use filters.

3. **Token refresh localStorage**: Refresh tokens stored in localStorage - standard browser security applies.
